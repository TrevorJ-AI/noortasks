# M5 server: shapes, rules, and decisions where sources are silent or conflict

Every choice below applies to the M5 server slice (`apps/server` and `packages/core`). Clock and timezone remain injectable (`Service.now()`, stored `settings.timeZone`, `settings.startDayOfWeek`).

## Reminders, Recurrence, and Holidays
- **RMD-005 negative all-day trigger convention**: `apps/web/src/ui/DatePicker.tsx` and `packages/quickadd/src/reminders.ts` apply standard RFC 5545 duration subtraction from local midnight (`TRIGGER:-P0DT15H0M0S` = 1 day early 09:00, `TRIGGER:-P1DT15H0M0S` = 2 days early 09:00, `TRIGGER:-P2DT15H0M0S` = 3 days early 09:00). Server `computeTriggerInstant` implements standard duration arithmetic to stay consistent with `packages/quickadd` and `apps/web`.
- **End-anchored triggers (`RMD-006`)**: `parseTriggerList` accepts both `TRIGGER;RELATED=END:...` and object-level `isBeforeStart: false` / `related: "END"`, anchoring against the occurrence `dueDate` (falling back to `startDate` when no `dueDate` exists).
- **Instances query endpoint (unobserved)**: `GET /api/v2/reminder/instances?from=<ms|iso>&to=<ms|iso>` computes and returns `ReminderInstance[]` across open tasks, open checklist items, active habits, non-deleted countdowns, and daily summaries. Defaults to `[now - 60_000, now + 86_400_000]` when omitted; inverted ranges return `400 invalid_date_range`.
- **Recurring completion (`RMD-027`)**: Added `POST /api/v2/project/:projectId/task/:taskId/complete` backed by `@noortasks/recurrence` `completeRecurringTask`. Relative `reminders` triggers stay untouched; `remindTime` and `snoozeReminderTime` are cleared on both the completed copy and the rolled-forward open task.
- **Close & Delay routes (`TASK-148`)**:
  - `POST /api/v2/task/closeRemind` accepts `{ taskId, itemId?, reminderId?, triggerTime? }`, `{ id }`, `{ tasks: [...] }`, or an array; returns `{ id2etag, id2error }`. Clears `snoozeReminderTime` / `remindTime` and writes a persistent high-water mark into `reminder_acks` so dismissed reminders and constant-reminder loops stop re-firing for acknowledged instants. Single-object calls return `404 task_not_found` / `404 item_not_found` when missing; batch forms record `NOT_EXISTED` in `id2error`.
  - `POST /api/v2/reminder/delay` accepts `{ taskId, itemId?, delayMinutes|minutes|snoozeMinutes }` or `{ snoozeReminderTime|snoozeTime|delayUntil }`; returns `{ snoozeReminderTime, id2etag, id2error }`. Updates `snoozeReminderTime` on the task or checklist item, acknowledges any active constant-reminder cycle up to `targetMs - 1` so constant alerts pause until the snooze instant, and logs `T_REMINDER` in `activities`.
- **Constant reminder (`RMD-022..024`)**: Enabled per task/habit/countdown via `annoyingAlert === -1` (`CONSTANT_REMINDER_FLAG`) or globally via `ext.reminder.annoyingAlertEnabled === true` (filtered by `ext.reminder.annoyingRemindItems` when present as an array). When active and unacknowledged, `computeInstances` emits 60,000 ms (`CONSTANT_REMINDER_CYCLE_MS`) cycles from `fireAtMs` up to `toMs` (capped at 1000 cycles per query).
- **Daily summary (`RMD-030..031`)**: Reads `dailyReminder` doc (or `settings.dailyRemindTimeConfig` fallback). Writes to `PUT/POST /api/v2/user/preferences/settings` with `dailyRemindTimeConfig` synchronize into `dailyReminder` and vice versa when `dailyRemindTimeConfig` exists. `weekDays` matches 2-letter uppercase prefix (`SU..SA`) against `WEEKDAY_CODES`. `holidayNotify: false` skips days where `holidays.isHoliday(date)` is true. `notifyOptions` accepts `TODAY` and `OVERDUE` (defaulting to both when empty) and summarizes open non-NOTE tasks.
- **Holiday store (`RPT-061..062`)**: Stored in `docs("holidays")` and exposed via `GET` / `PUT /api/v2/holidays` with shape `{ restDays: string[], workDays: string[] }` (`YYYY-MM-DD`). With empty holiday doc, Saturdays and Sundays are rest days (`weekendOnlyProvider`). Regional country holiday calendars are not bundled; admins or clients can populate `holidays` via API.
- **Email notifications (`NTF-014..016`)**: Preferences (`settings.isEmailEnabled`, `ext.general_conf.emailRemindEnabled`, `emailRemindItems`) are persisted with no daily count cap; outbound SMTP transport is out of scope for this offline self-hosted M5 pass.

## Web Push, VAPID, and Notification Centre
- **VAPID key configuration**: `NOORTASKS_VAPID_FILE` (or `AppOptions.vapidFile` / `AppOptions.vapid`) points to a JSON file `{ publicKey, privateKey, subject }`, generated via `pnpm --filter @noortasks/server exec tsx src/cli.ts generate-vapid <file> [--subject mailto:...]`. `GET /api/v2/push/vapidPublicKey` returns `{ publicKey: string | null }`.
- **Push registration & arrival**: `POST /api/v2/push/register` accepts `{ pushToken, osType, hl?, subscription? }` (either explicit `subscription` or JSON-encoded Web Push subscription in `pushToken`), stores in `push_subscriptions`, deduplicates on `pushToken`, and increments `version`. `POST /api/v2/push/stats/arrive` returns `{}` (accepted telemetry).
- **Dispatch scheduler**: `main.ts` runs `reminders.dispatchDue()` every 30s (cleared cleanly on `onClose`). Dispatch skips when `settings.notificationEnabled === false` or `isNotificationEnabled === false` or when no VAPID keypair is configured. Uses `web-push` `sendNotification` (`aes128gcm` + VAPID `Authorization`), deduplicates per `(kind, targetId, reminderId, fireAtMs)` in `reminder_deliveries`, inserts first delivery per reminder occurrence into `notifications`, and removes stale subscriptions when upstream returns HTTP `404` or `410`.
- **Notification centre (`NTF-002..004`)**: `GET /api/v2/notification?autoMarkRead=true|1|false`, `GET /api/v2/notification/unread` (`{ notification, activity }`), `PUT /api/v2/notification/markRead?category=activity|notification|all`.
- **Preferences `ext` mtime merge**: `PUT/POST /api/v2/user/preferences/ext` merges per top-level key comparing numeric `mtime` (stale section writes with `mtime < existing.mtime` are skipped). `GET /api/v2/user/preferences/ext?mtime=<n>` returns only sections with numeric `mtime > n`.

## Comments & Unlimited Attachments
- **Comments (`TASK-117..120`, `TASK-147`)**: Stored in `comments` table. Routes `GET .../comments`, `POST .../comment`, `PUT .../comment/:commentId`, `DELETE .../comment/:commentId`. Validates parent task existence (supports `"all"` wildcard for `projectId`), rejects deleted tasks (`400 task_deleted`), rejects empty text without attachments (`400 empty_comment`), validates reply `commentId`, enforces unique `id` (`409 comment_existed`), keeps unknown fields, imposes zero text-length or image-count limits, updates `task.commentCount`, bumps task `seq`/`etag`, and records `T_COMMENT_ADD` / `T_COMMENT_EDIT` / `T_COMMENT_DEL` activities.
- **Comment & unlimited attachments (`ATT-001..025`, `ATT-901`)**: `POST /api/v1/attachment/upload/comment/:projectId/:commentTaskId` streams multipart files into `dataDir/attachments/` with `taskSet = "comment"` (does not mutate `task.attachments`) and uncapped file size/count (`bodyLimit: Number.MAX_SAFE_INTEGER`). Deleting a comment removes its `comment` attachments; permanent task deletion removes all comments and their comment attachment files. `GET /api/v1/attachment/isUnderQuota` returns `true`; `GET /api/v1/attachment/dailyLimit` returns `1_000_000_000`; `GET /api/v1/attachment/storage` returns `checkDiskSpace(dataDir)` (`lowDisk: true, warning: "low_disk_space"` when `freeBytes < 1 GiB`).

## Templates
- **Fresh DB seeding (`TPL-004`)**: Empty DB seeds 3 starter `taskTemplates` (ordered `0, 1, 2`), 3 starter `noteTemplates` (without `order`), and 3 `projectTemplates` ("Weekly Meal Plan", "Product Launch", "Bug Triage"). `importExport.ts` `importBackup` marks seeding flags so imported snapshots remain verbatim.
- **Routes**: `GET /api/v2/templates`, `POST /api/v2/templates/task|note` (supports single object, `Save as Template` extraction when `taskId` is given without explicit title, and `{ add, update, delete }` batch; unlimited title length and count), `PUT/DELETE /api/v2/templates/task|note/:id`, `POST /api/v2/templates/task|note/order`, `GET /api/v2/projectTemplates/all?timestamp=<seq>` (`seq`-based incremental delta), `GET /pub/api/v2/templates/project/:id` (public, unauthenticated) and `GET /api/v2/templates/project/:id`, `POST /api/v2/templates/project/:id/apply` (creates project, columns, tasks, subtasks linking `childIds`, sync delta, and `P_CREATE`/`T_CREATE` activities).

## Filters, Search, and Activity Log
- **Filter rules (`FILT-006..011`, `FILT-020`)**: `packages/core/src/filterRule.ts` implements `team`, `calendar`, `account`, and `custom(start~end)` tokens in addition to all M1-M4 conditions; unknown condition names evaluate to `false` (`FILT-008`). Server `POST /api/v2/batch/filter` is uncapped (`PREM-094`) and syncs incremental `filters` and `deletedFilters` tombstones via `batch/check/:cp`.
- **Search (`SRCH-008`)**: `GET /api/v2/search/all` (`keywords|keyword|q`, `projectId`, `tag`, `priority`, `date`, `status`) delegates to `evaluateRule` over non-deleted tasks.
- **Activity log (`TASK-055`, `TASK-121..122`, `TASK-146`)**: Recorded across task create/update/complete/wontdo/reopen/field edits/tag rename/parent/move/trash/restore/delete/attachments/comments/reminder delay and project/column CRUD. Served at `GET /api/v1/task/activity/:id`, `GET /api/v1/project/:id/activity`, and `POST /api/v2/task/activity/count/all`.

## Import, Export, and Backup
- **Verify gate (`x-verify-id`)**: `POST /api/v2/user/verify` verifies the passphrase when auth is enabled (401 on wrong passphrase) and issues a 15-minute `verifyId` token. In `--no-auth` mode it issues a token unconditionally. Both `GET /api/v2/data/export` and `GET /api/v2/data/export/auto` require a non-empty valid `x-verify-id` header (403 otherwise) and never rate-limit (`PREM-124`). `GET /api/v2/data/export/link/:id/check` immediately answers ready.
- **Backup CSV & Restore Merge**: Exports RFC 4180 CSV using the exact 23-column `BACKUP_CSV_HEADER` across all non-deleted tasks (open, completed, won't-do). Standard 23-column backup CSV omits `Kind`, so checklists preserve via `Is Check list = Y/N` while `NOTE` distinction flattens to `TEXT`; `importTasksCsv` detects the header dynamically, strips UTF-8 BOM, parses optional backup metadata preambles and status legend (`2` -> `WontDo`), accepts optional `Kind` column when present, clamps out-of-range `Order` via `clampOrder`, creates/reuses folders, lists (`viewMode`), columns, and tags, links subtasks cleanly on pass 2 (ignoring cycles/depth > limit), and uses first-wins conflict handling (existing `taskId` rows are skipped).
- **Habit, Focus, and Single-task Exports**: `GET /api/v2/data/export/habits?format=csv|xlsx` (default `.xlsx`), `GET /api/v2/data/export/pomodoro?format=csv|xlsx` (default `.csv`) using a dependency-free ZIP/OOXML `buildXlsx` builder with `node:zlib` CRC32, and `GET /api/v2/task/:id/export` serving Markdown.
- **Third-party importers (`IMP-026..033`)**: Out of scope for this M5 server pass.
- **Backup snapshot directory (`importExport.ts`)**: M5 `comments`, `activities`, and `notifications` round-trip via `comments.json`, `activities.json`, and `notifications.json` without changing M1-M4 snapshot formats.

## Follow-ups 2026-11-16
- **Named matrix profiles (`MTRX-007..019`, `PREM-056`, `PREM-068`)**: Stored in `matrix_profiles` with empty `[]` initial state and no count cap; `GET /api/v2/matrixProfiles` returns profiles sorted by `sortOrder`; `POST /api/v2/matrixProfiles` accepts a single profile object (upsert, minting `id` if missing), an array of profiles, or `{ add, update, delete }`; `POST /api/v2/matrixProfiles/batch` (and `/matrixProfiles/batch` alias) runs `{ add, update, delete }`; unknown fields are preserved and `matrix-profiles.json` round-trips through `importExport`.
- **Column deletion tombstones (`KANB-*`, `SYNC-*`)**: `GET /api/v2/column?from=<columnTimeStamp>` accepts numeric ms `seq` or wire ISO timestamps (`0` returns full `Record<string, Column[]>` snapshot). When `from > 0`, deleted column tombstones recorded in `tombstones` (`kind = "column"`, with `projectId` fallback from stored column on delete when omitted from payload, and cascading project deletes) are appended to `out[projectId]` as `{ id, projectId, deleted: 1 }` alongside changed columns, skipped if the same column id is currently live.
- **Countdown card image upload (`ATT-902`)**: `POST /api/v1/attachment/upload/countdown` (optional `?attachmentId=<id>`, validated against `SAFE_ID` when non-empty and minted via `newId` otherwise) streams multipart bytes without size or count caps into `attachments` (`taskSet = "countdown"`, `taskId = ""`, `projectId = "countdown"`). Downloads work via `/api/v1/attachment/:id` and `/files/upload/*`, and `DELETE /api/v1/attachment/:id` deletes countdown attachments without touching tasks.
- **Habit & focus CSV exports (`IMP-022..023`)**: `GET /api/v2/data/export/habits` and `GET /api/v2/data/export/pomodoro` (already added in M5) accept case-insensitive `?format=csv|xlsx`; `habits` also honors `Accept: text/csv` when `?format` is omitted (otherwise `.xlsx`), reads `mood` with `emoji` fallback, and `pomodoro` defaults to CSV.
- **Task focus estimates (`FOC-017`)**: On `POST /api/v2/batch/task`, client writes to `focusSummaries` control only the estimate fields (`estimatedPomo`, `estimatedDuration`, sanitized to finite non-negative numbers) plus any unknown entry keys, while the server owns `userId` and the counted fields (`pomoCount`, `pomoDuration`, `stopwatchDuration`, `focuses`). Omitting `focusSummaries` preserves stored summaries verbatim; sending `[]` or `null` clears estimates while retaining `focusSummaries[0]` if any counted focus values are non-zero. `FocusService.refreshSummaries` retains `focusSummaries` when all focus records are deleted as long as `estimatedPomo > 0` or `estimatedDuration > 0`.
- **User ranking percentile (`ACC-019`)**: `GET /api/v3/user/ranking` returns `ranking: 0.99` (fixed placeholder without cross-user leaderboard computation).
